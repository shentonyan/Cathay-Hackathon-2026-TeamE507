# 开发路线

以下是起步待办，尚未代表团队已作出技术或产品承诺。任务进入开发前，由团队在 Issue 中补齐负责人和验收标准。

## M0 · 协作就绪

- [x] 代码目录、README、协作模板和本地预览工具。
- [x] 格式检查、基础测试和 CI 工作流。
- [ ] 邀请队友，所有成员完成一次本地启动。
- [ ] 确认角色、沟通方式与代码审阅安排。
- [ ] 按 GitHub 计划和团队需要配置 `main` 分支保护。

## M1 · 确认 MVP

- [ ] 明确 Cathay AaaS 构想下的首个用户和一个核心场景。
- [ ] 确认本次实现与 mock 的边界。
- [ ] 选定前后端框架并记录架构决策。
- [ ] 确认页面流程、API 契约和合成样例数据。

## M2 · 实现可演示闭环

- [ ] 首屏 → 核心操作 → 结果的完整流程可运行。
- [ ] 补齐加载、空数据和错误状态。
- [ ] 新电脑按 README 可以重复启动。
- [ ] 核心行为和接口有相应测试，CI 能检查新增模块。

## M3 · Demo 与交付

- [ ] 按 [演示清单](DEMO.md) 完成彩排和故障备用方案。
- [ ] README 写清实际完成的功能与限制。
- [ ] 整理提交物，确认使用资料的授权范围。
- [ ] 记录最终 commit，按需要创建版本标签和 Release。
